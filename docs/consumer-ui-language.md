# 消费者界面语言规范

PriceAI 是面向普通消费者的全品类购物决策与比价平台。当前手机数据仅代表已收录范围，不能把通用页面表述为手机专用服务。

- 中文优先，保留品牌名、型号和 PriceAI 名称。代码和数据类型的内部命名不必翻译。
- 统一使用：PriceAI 评分、AI 购买建议、历史价格、平台报价、商品规格、商品对比、榜单。
- 区分 PriceAI 评分与平台报价中的平台评分，不推断未明确提供的评分来源。
- 不向消费者展示 SKU、Variant、Offer、Catalog Sync、Price Snapshot 等内部术语。
- 文案短、自然。购买判断应在一至两行内说明已有数据支持的事实。
- 价差必须说明同一规格及比较对象，不把价差当作综合评分的完整解释，不承诺全网最低价。
- 通用品类入口、筛选组件使用数据传入的标签与选项；没有数据支持的尺码、材质等筛选项不展示。
- 手机榜单等确实限定品类的页面保留准确品类名称；不虚构其他品类已经可用。
- 不伪造商品、价格、销量、评分、优惠、历史记录或平台报价。示例数据必须说明是示例数据。
- 手机端排序选项完整可见，筛选默认折叠；主要按钮触摸区域不小于 44px。
- 商品卡使用“购买参考”；搜索提示使用“搜索你想买的商品”。
- 评分展示档位沿用既有阈值：90–100 很值得买、80–89 比较值得买、70–79 可以关注、60–69 表现一般、低于 60 谨慎考虑。评分是综合结果，不用“价格一般”代替整体评价。
- 核心规格由展示层的 `specificationSummary` 生成：优先使用数据提供的有序 `coreSpecifications`，手机旧目录按独立品类映射兼容。未知品类没有摘要时不套用手机字段、不编造规格。未来数据接入仍需适配现有目录类型与数据管线，本轮不改这些业务接口。
- PriceAI 不承接下单、支付、物流或售后。只有平台报价包含经过校验的真实 `http/https` 商品地址时，消费者页面才显示“去购买”，并明确该操作将在新标签页打开第三方购物平台；无可靠地址时不显示购买按钮。
